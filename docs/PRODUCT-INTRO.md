# Sketch Plan 产品详情介绍

> 对应版本：Web v1.8.2　|　文档性质：产品功能说明

---

## 一、产品定位与核心价值

Sketch Plan 是一款面向个人的日程与时间规划 Web 应用，浏览器直接访问，无需安装。产品以输入极简、结构自洽、数据自主为前提，结合纸质手账的记录手感与数字化工具的结构能力：用户以接近书写的成本录入，系统以统一模型承载，并在多视图与统计上一致呈现。

核心价值体现在三个方面。

**录入成本接近书写。** 内置中文速记解析，输入“明天下午三点组会 1 小时 提前 20 分钟”，即可生成含日期、时间、时长、提醒与分类的完整事件。常规工具完成同一操作通常需六步以上，速记路径为一次输入加一次确认，这是记录习惯能否建立的前提。

**单一数据源支撑多视图。** 事件、长期计划、工作集与复盘共享同一份数据，月历、周表、时间轴、进度与工作集均为其投影，不存在多口径维护与视图间延迟。

**复盘成为内建能力。** 周完成率、分类时长分布、每日完成情况与三问记录同页生成，计划与执行可直接对照，无需导出表格二次统计。

产品面向以周为单位安排工作与学习、希望低成本记录并定期回顾的个人用户，以“记录—查看—完成—复盘”闭环为边界。

## 二、主要功能

**速记输入。** 可识别相对日期（明天、下周一）、绝对日期（10 月 28 日、28 号）、时刻（14:30、下午三点半）、时长（2 小时、90 分钟）、重复规则（每天、工作日、每周一三五、每 3 天）与提醒提前量。解析结果先预览、确认后写入，避免误解析直接落库。

**多视图日程。** 提供月、周、时间轴、进度四个主视图。月历以网格呈现整月分布并标记有安排的日期；周表按七天列排布，用于检视一周时间占用；时间轴按 06:00 至 24:00 定位事件并标注当前时刻；进度视图汇总长期目标与打卡情况。

**工作集。** 跨时间的任务容器，含名称、分类、备注、起止时间与关联日程，按关联日程的完成情况自动计算进度，支持展开明细，适合承载一个项目或一个阶段目标。

**分类体系。** 内置学习、工作、生活、健康四类，支持增改与删除；删除前校验该分类下是否存在内容，存在时要求先迁移，避免数据悬空。

**重复日程与推迟。** 重复事件以系列标识归组，支持整组查看、整组删除与单次删除；单次事件可推迟至次日，并记录推迟原因，推迟次数计入复盘，用于识别长期被顺延的事项；事件可拆分子任务并逐项勾选，批量排课可一次为多天安排同一事件。

**长期计划与打卡。** 以目标值、单位与每日记录追踪跨周目标（如“阅读 32 篇”“跑步 100 公里”），累计完成量并计算百分比与剩余量，同时展示起止日期。

**周复盘。** 按周汇总事件总数、完成数、完成率、总时长与推迟次数，输出分类时长占比与每日完成柱状，并提供三问记录区：做到了什么、卡在哪里、下周如何调整。

**便签、搜索与导出。** 便签用于临时记录；全局搜索按标题与备注检索并跳转对应日期；支持导出全部数据为 JSON，便于迁移与备份。

**主题与快捷键。** 纸墨、柔彩、夜航三套主题对应纸质书写、白天办公与夜间专注，切换仅替换设计令牌，不改结构，不引起布局跳动。常用操作提供键盘快捷键，桌面端可脱离鼠标操作。

**账号与数据模式。** 登录后日程与计划同步至账号，换设备可见同一份数据；未登录时进入浏览器本地模式，数据仅留在当前设备，两种模式在界面上有明确标识。

## 三、技术参数

| 项目 | 参数 |
|---|---|
| 产品形态 | Web 应用，浏览器直接访问，桌面与手机自适应 |
| 视图数量 | 8 个（月、周、时间轴、进度、工作集、分类、复盘、我的） |
| 前端技术 | 原生 JavaScript / HTML / CSS，不依赖第三方 UI 框架 |
| 前端资源 | 主脚本约 121 KB，全部脚本合计约 206 KB |
| 服务端 | Node.js + SQLite，提供 REST 接口 |
| 数据表 | 10 张（用户、会话、工作集、事件系列、事件实例、提醒、计划、打卡、复盘、设置） |
| 同步策略 | 本地先改（乐观更新）→ 提交 → 以服务端数据重建；写失败回滚重拉 |
| 提醒机制 | 后台任务每 30 秒扫描到期提醒并标记投递，前端触发站内提示 |
| 备份策略 | 每日 03:10 生成一致性快照，保留 14 份 |
| 动效参数 | 过渡 700 ms + 停顿 60 ms + 淡出 220 ms；减少动效偏好下 240 ms |
| 部署方式 | 提供 Docker 镜像与容器编排配置，可自托管 |

**统计口径。** 完成率 = 已完成事件数 ÷ 区间事件总数，按自然周计，起始日可设为周一或周日；时长以分钟累计，展示为小时并保留一位小数；分类占比 = 分类时长 ÷ 区间总时长。

**数据模式。** 云端模式数据存于服务端 SQLite，按账号隔离；本地模式存于浏览器 localStorage，容量受浏览器策略限制。两者不自动迁移，切换前应导出 JSON 备份。

**兼容性。** 要求支持 CSS 自定义属性与现代布局能力的浏览器；移动端采用独立布局，功能入口按屏幕宽度重排。

## 四、使用场景

**学业管理。** 将课程、作业与考试录入同一日历，通过月历观察考试周的时间压力，以长期计划追踪学期目标。

**职场执行。** 会议密集的岗位可在时间轴确认当日时间占用，识别连续会议造成的整块时间缺口；以工作集承载项目周期，按关联日程完成情况判断推进状态。

**多项目并行。** 自由职业者可分项目建立工作集，通过分类时长占比观察精力分配是否与优先级一致，减少“忙但产出不可见”的情况。

**备考与习惯养成。** 语言考试、体能训练等长期目标适合以打卡追踪，完成百分比与剩余量提供明确反馈。

**周度复盘。** 每周固定 10 分钟查看完成率、分类时长占比与推迟事项，回答三问并记录调整，使下一周安排建立在上一周的事实之上。

**多设备与自托管。** 需在办公室与家中查看同一份安排的用户可用账号同步；对数据存放位置有要求的用户可自行部署，数据留在自有服务器。

## 五、差异化优势

**输入成本低。** 以中文短句替代多步表单，是与通用日历工具的主要区别。按常规路径估算，录入一个含日期、时间、时长与提醒的事件需六次以上交互，速记路径为一次输入加一次确认（估算值，实际因浏览器与版本而异）。

**数据一致。** 单一事实源使各视图同步，不存在“日历改了、进度未更新”的问题；服务端以事件系列与事件实例分离建模，重复日程的例外处理不影响整组。

**响应即时且可回滚。** 写操作先在本地生效再提交，界面不等待网络往返；失败时自动回滚并重拉服务端状态，避免“界面已改、数据未存”。

**视觉可切换。** 三套主题共享网格与组件尺寸，切换只改色彩、描边、圆角与字体，不改信息结构。

**复盘链路完整。** 从速记录入到周度统计在同一产品内完成，推迟原因与分类时长占比可直接指向行为问题。

**可自托管。** 服务端以单文件数据库与容器镜像交付，不依赖第三方云服务；用户可自行部署、备份与迁移。

## 六、适用人群

| 适合人群 | 匹配理由 |
|---|---|
| 学生与备考者 | 课程作业密集，需月历视角与长期目标追踪 |
| 职场个人贡献者 | 会议与交付并行，需快速记录与周度复盘 |
| 自由职业者 | 多项目分桶，按分类时长观察精力分配 |
| 重视数据自主的用户 | 可自托管，支持导出 JSON 与定期备份 |

需明确当前不适用情形：不支持团队协作、共享日历与多人排期；不与审批、工时或目标管理系统对接；不与系统日历或第三方日历双向同步；不适用于十万级条目以上的强检索分析场景。上述能力属不同产品定位。

## 七、总结与使用建议

Sketch Plan 以低成本的速记输入、单一数据源的多视图呈现与内建的周度复盘，回应个人时间管理的三个常见问题：记录难以坚持、安排看不出结构、复盘缺少依据。产品不覆盖协作与企业场景，以个人闭环的完整性为取舍标准。

建议按以下顺序使用：

1. **前三天只记录。** 使用速记录入，不急于建立分类与工作集，先建立“想到即记”的习惯。
2. **第四天建工作集。** 选择一至两个进行中的项目，将相关日程关联进去，使进度可自动计算。
3. **每周固定复盘。** 只关注完成率与分类时长占比，结合推迟次数与原因判断哪些安排长期不可执行。
4. **按场景选主题。** 长时间书写用纸墨，白天办公用柔彩，夜间专注用夜航。
5. **先定数据模式。** 跨设备使用则登录并启用同步；单机使用可选本地模式，但应定期导出 JSON 备份。

本介绍基于当前发布版本编写，功能与技术参数以实际版本为准；存储容量与浏览器能力描述受对应平台规则约束。
